What the settle is doing It is a subtraction, not a transition. A cross-fade into a second component would ask a new person to re-find five things they had just watched arrive. Instead the runtime rows hold their positions and the process falls away around them: preamble collapses to nothing, $ and --version fade to zero width, leader dots draw in, the status dot appears, and the result slides to the right edge because the space in front of it opened up. Nothing animates into place — place is where it already was. The one swap is the name, claude to Claude Code, cross-fading in a fixed-width cell so nothing reflows. That is worth the one exception: the binary name is what the terminal truthfully ran, and the product name is what the rest of the app calls it — so the settle is also the moment the screen hands you back into the app's own vocabulary. Where the honesty rule bites: if discovery finishes before the settle would have started, there is no settle — the screen simply shows the table. The animation is a way of ending a wait, never a reason to have one. Use Step to to sit in each phase, and note that the whole settle is 420ms. Under prefers-reduced-motion the settle should be instantaneous rather than removed — the end state is information, so it must still arrive; only the movement goes.
