The billing adapter has three problems and they compound. First, the v2 payload mapper assumes every event carries a currency field, which was true until the 2026-04 API version split it into presentment and settlement currency — so anything that came in after that has been silently defaulting to the account currency and the totals have been right by luck. Second, the dispute events changed shape in the same release and the adapter has no branch for the new one, which means a dispute either parses as an empty object or throws depending on whether the amount happens to be present. Third, and this is the one that will bite during the migration, the flag that is supposed to gate the whole thing is read once at module load rather than per request, so flipping it does nothing until the process restarts. I would fix them in that order, because the first is a correctness problem that is already live, the second only affects a code path that fires a few times a week, and the third is not wrong yet but will make the rollout untestable.
