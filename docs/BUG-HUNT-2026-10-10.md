# Bug hunt: Locust 0.715.0 (main at e395f57ac), 2026-10-10

One agent, no subagents. Two full reads of every line in scope, experiments and
failing tests in a scratch copy of the repository, and each fix checked on that
copy. During the hunt nothing left the sandbox and nothing was installed or
downloaded; the dependency store that was already present was used to build
the two packages and run the tests.

## The top bugs in a few lines

1. A Copilot teammate's chosen effort is never sent. The Approve-each (ACP)
   command builder has no effort at all and the print route's call site leaves
   it out, so every Copilot run uses the CLI default while the thread shows the
   level that was picked. (High)
2. Keeping a skill from a GitHub link that points at a folder keeps the FIRST
   folder of that name anywhere in the repository, not the one shown; with a
   SKILL.md at the repository root, Keep refuses outright. (Medium)
3. A terminal prompt longer than 8,000 characters makes terminal catch-up throw
   at that exchange forever: everything typed in the terminal after it is lost
   to the record. (Medium)
4. Antigravity: a transcript read that fails once is never retried, so the run
   idles out with its answer unread; and a timer set on a task that already
   ended holds the turn open until the idle limit. (Medium, two bugs)
5. A failed Muse task or Copilot tool whose reason is over 512 characters makes
   the ledger refuse the event and the host end the run. (Medium, two bugs)
6. On macOS and Linux, OpenCode worktree runs are handed an allow pattern
   written with backslashes, so the one directory the pattern exists for is
   never allowed. (Medium)

22 bugs were demonstrated with failing tests in all. The full list follows,
then what was confirmed by reading only, what was rejected, and what was not
checked.

## Scope and method

- Code: the logic layer: apps/desktop/src/main, src/shared and src/preload,
  packages/mission-store/src, packages/runtime-adapters/src, and
  apps/desktop/resources/*.mjs. 255 files, 78,138 lines, read in 54 slices.
  The renderer (66,964 lines) was excluded and is not covered here. ipc.ts was
  read whole in pass 1 and by its functions and constants in pass 2.
- Pass 1 read for loops, index arithmetic, boundaries, recursion, sorting,
  parsing, state mutated while read, error paths and promises not kept. Pass 2
  read every slice again for what pass 1 could not see: wrong defaults, wrong
  return values, dropped branches and conditions, swapped arguments, wrong
  constants. Grep sweeps afterwards: setTimeout with computed delays, default
  sort(), spread max/min, parseInt without radix, || defaults, toISOString on
  parsed input, relative() argument order.
- 95 numbered suspicions were written down (24 rated 3, 42 rated 2, 29 rated 1;
  a few are the same finding seen twice). 25 went to the proof phase: 22 were
  demonstrated with a failing vitest test through a public interface, 2 are
  confirmed by reading only, 1 was narrowed and rejected.
- Every fix below was applied on the scratch copy. All 23 proof tests then
  pass, the mission-store suite passes, and the remaining failures in the other
  suites are pre-existing on Linux (listed at the end). tsc is clean for the
  three packages with the fixes applied.
- The proof tests and the combined patch are in docs/bug-hunt-2026-10-10/.

Severity follows the brief. High: ordinary input gives a wrong result
silently, loses data or never finishes. Medium: a crash on ordinary input, or
wrong only on unusual input. Low: the rest. Between two labels the lower one
was chosen.

## Confirmed bugs, worst first

### High

#### 1. CA1: a Copilot teammate's chosen effort never reaches the run

- Where: packages/runtime-adapters/src/commands.ts, createCopilotAcpCommand
  (lines 1849-1858) has no effort option; apps/desktop/src/main/codex-mission.ts
  lines 2025-2028 (the ACP branch) and 2031-2037 (the print branch) build the
  Copilot command from the model and the session only, while every other
  runtime gets `...choice`, which carries the effort (lines 1974-1979).
- Input: a Copilot teammate with an effort chosen (the picker offers
  none/minimal/low/medium/high/xhigh/max, read from `copilot --help`), in any
  mode.
- Expected: `--effort <level>` on the command line, as the print builder's own
  comment promises ("either alone would leave the app offering a level it
  refuses to send, or refusing one it offers").
- Actual: no `--effort` in either route. The run starts at the CLI default; the
  thread, and the route saved for the teammate, show the chosen level.
- Failing tests: runtime-adapters ca1-copilot-effort.test.ts ("rides on the ACP
  command too": the args are `--acp`, the excluded-tools flag, `--model
  gpt-5.6` and nothing else); desktop ca1-copilot-effort-call-site.test.ts
  ("reaches Copilot": through createCodexMissionService(...).start('Say hi.',
  'copilot', 'ask', { effort: 'high' }, ...) the launched argv is `-p Say hi.
  --output-format json --allow-all-tools --no-color
  --excluded-tools=session_store_sql --deny-tool=write,shell --session-id ...`;
  the Codex control in the same file passes).
- Fix (checked): in createCopilotAcpCommand add `if (options.effort !==
  undefined) args.push("--effort", requireEffort(options.effort))`; in both
  Copilot branches of codex-mission.ts add `...(chosenEffort === undefined ? {}
  : { effort: chosenEffort })`. The ACP half assumes `copilot --acp` takes
  `--effort`, which the builder's comment at line 1676 says was measured.

### Medium

#### 2. SL1: Keep from a folder link keeps a different folder than the one shown, or refuses

- Where: apps/desktop/src/main/skill-library.ts. preview lists
  skillsInTree(tree, repo, parsed.path) (line 339); install lists
  skillsInTree(tree, repo) over the whole tree (line 388) and takes the first
  unheld folder of each name (lines 391-397). The install request
  (shared/ipc.ts SkillLibraryInstallRequest, line 1344) carries no folder.
- Input: a link such as github.com/o/r/tree/main/b where the repository holds
  a/foo/SKILL.md and b/foo/SKILL.md; or a link to a folder of a repository
  whose root has a SKILL.md of its own.
- Expected: Keep foo keeps b/foo, byte for byte what the list described (the
  file's own promise).
- Actual: a/foo sorts first over the whole tree, b/foo is held as a twin, and
  a/foo is downloaded and kept under the name foo. With a root SKILL.md,
  install finds only the root skill and Keep foo fails with "foo is not a
  skill Locust can keep from that commit."
- Failing test: desktop sl1-folder-link-install.test.ts (both cases; the first
  reads the kept SKILL.md and finds "The A foo." where the preview showed "The
  B foo.").
- Fix (checked): carry the previewed folder in the install request (an
  optional `path`) and call skillsInTree(tree, repo, under) in install. The
  renderer has to send the field; the copy adds it to the request type and to
  install only.

#### 3. TC1: a terminal prompt over 8,000 characters stops terminal catch-up for good

- Where: apps/desktop/src/main/terminal-catch-up.ts line 330 (`MAX_PROMPT =
  16_000`) and line 374 (bounded(exchange.prompt, MAX_PROMPT)). The ledger
  refuses a prompt over 8,000 (packages/mission-store/src/index.ts lines 189
  and 803). session-import.ts line 55 uses 8,000 with a comment naming the
  ledger bound.
- Input: a Locust Claude Code or Codex conversation continued in the terminal,
  where one typed prompt is longer than 8,000 characters (a pasted log).
- Expected: the exchange comes back, bounded, and the exchanges after it come
  back too.
- Actual: createMission throws "prompt is invalid" at that exchange.
  imports.write only advanced past the earlier exchanges, so every later
  catch-up (every focus of the window) fails at the same exchange; nothing
  typed in the terminal after it ever reaches the record.
- Failing test: desktop tc1-terminal-prompt-bound.test.ts (catchUpTerminal
  with the real file ledger: a 9,000-character cli prompt followed by a short
  one; expected imported 2, actual an "Error: prompt is invalid" rejection,
  and the second call rejects the same way).
- Fix (checked): `MAX_PROMPT = 8_000`.

#### 4. RL1: the second thread waiting on a busy teammate never hears how the held reply ended

  (line 1106); onRunEnded reads one exchange per mission (lines 1399-1414).
- Input: teammate B mid-run; A shares to B (held), then C shares to B before

#### 5. AM1: an Antigravity transcript read that fails once is never retried

- Where: apps/desktop/src/main/antigravity-mission.ts poll, lines 618-621:
  `run.seen = info` is set before the read's result is known.
- Input: the transcript grew; readTranscript fails once (the file mid-write)
  and succeeds on every later tick.
- Expected: the next tick reads the growth and feeds its lines (the comments at
  629-637 and 716-731 promise exactly that for a ledger failure).
- Actual: every later tick sees "unmoved" and never reads again. The lines in
  that growth (the final answer, if it was the last write) are never fed; the
  run sits until the ten-minute idle limit and ends as if the agent wrote
  nothing.
- Failing test: desktop am1-transcript-read-fails-once.test.ts (the service
  with statTranscript constant and readTranscript failing once: tool.started
  never arrives and the file is read exactly once; the control with a good
  first read passes).
- Fix (checked): `if (!unmoved && text !== undefined) run.seen = info`.

## Confirmed by reading only (no failing test)

Two candidates rated 3 were not given a test:

- AC1 (with A2/A3): packages/runtime-adapters/src/acp-run.ts converse (lines
  404-405) leaves the prompt loop on any stopReason other than end_turn, and
  acp-events.ts finish (lines 417-441) records run.completed for every
  stopReason but refusal. An ACP turn cut off by max_tokens or
  max_turn_requests is therefore recorded as finished, with no word; and
  steer() answers true ("it will be sent") for a message queued during such a
  turn that is then never sent. A harness needs an ACP agent stand-in.
  Sureness 4 by reading.
- CR2: apps/desktop/src/shared/command-reach.ts splitChain (lines 332-338)
  keeps a parenthesised group or a command substitution whole on purpose, so

  a process-ending command whose verb sits inside parentheses, inside `$( )`,
  or in a loop body; runners that commandWords does not strip (`timeout 10

  allow this session" where the host would otherwise refuse the reach; the
  saved-rule path is still refused by the COMPOUND test. Not given a test on
  purpose, since the inputs are destructive command lines. Sureness 4 by
  reading.
